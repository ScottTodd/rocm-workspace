## Summary

This PR adds a package-scoped path for regenerating PEP 503 package indexes in
`build_tools/third_party/s3_management/manage.py`. The full-sweep behavior stays
as the default, while callers can pass `package_name` with
`update_root_index=False` to list only objects for the affected wheel package
and avoid rebuilding every package index under the prefix.

The current head has addressed the main correctness trap from earlier review:
`update_pep503_index()` rejects `package_name` combined with
`update_root_index=True`, so a package-scoped object list cannot overwrite the
root `{prefix}/index.html` page.

## Overall Assessment

**APPROVED with an important follow-up** - I did not find a blocking correctness

## Findings

### IMPORTANT: Package-scoped no-match path silently succeeds

[`_make_list_prefix()`](https://github.com/ROCm/TheRock/blob/84a55bf33201030f5711dcca829ced17b42a3519/build_tools/third_party/s3_management/manage.py#L70-L80)
uses `package_name` directly to form the S3 listing prefix, and
[`fetch_object_names()`](https://github.com/ROCm/TheRock/blob/84a55bf33201030f5711dcca829ced17b42a3519/build_tools/third_party/s3_management/manage.py#L452-L463)
now returns an empty list when that prefix has no `Contents`. In the scoped
path, [`update_pep503_index()`](https://github.com/ROCm/TheRock/blob/84a55bf33201030f5711dcca829ced17b42a3519/build_tools/third_party/s3_management/manage.py#L588-L601)
will then print `Fetched 0 objects`, upload/save nothing, and return `0` without
failing.

For a Lambda handling an S3 object-created event for an existing package, zero
matched objects is not a valid successful outcome. It means the caller passed a
package name that does not match the wheel filename distribution segment, such
as a PEP 503-normalized hyphenated name instead of the underscore form, a casing
mismatch, or unexpected bucket state. Returning success here would leave the
package index stale and make the failure hard to notice.

**Recommendation:** When `package_name` is provided and the filtered object list
is empty, raise a clear exception before upload/save. Also document or normalize
the accepted package-name representation at this API boundary. A small unit test
can cover this by monkeypatching `S3Index.fetch_object_names()` or
`S3Index.from_S3()` to return no objects for a scoped request.
